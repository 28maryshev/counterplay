# Counterplay Discord Bot

Бот Discord-сервера Counterplay. Читает тот же снимок базы статистики, что и
десктоп-приложение (GitHub release `data`), и превращает его в посты и ответы:

- **Meta Radar** — аномалия меты в #meta-radar раз в двое суток (10:00 UTC):
  недооценённый чемпион, растущий, ловушка, скрытый контрпик. После смены патча
  два выпуска подряд — режим Seismograph (крупнейшие сдвиги винрейта).
- **Draft Duels** — драфт-викторина в #draft-duels раз в трое суток
  (12:00 UTC), разгадка в 22:00 UTC, таблица недели в воскресенье 20:00 UTC.
  Правильный ответ — тот, кого выше всех оценил бы движок программы: оценка
  считается тем же ядром формулы (`lib/scoring.js`), без личной истории игрока.
- **Lab Verifier** — автопроверка находок в форуме #submit-finds;
  подтверждённые уходят в #hall-of-fame.
- **Pick Coach** — `/pool`, `/counter`, `/matchup` (ответы видит только
  спросивший, работают везде).
- **Patch watch** — раз в час сверяет официальный патч и свежесть наших данных;
  при выходе патча постит в #announcements, что именно Riot изменил: цены,
  характеристики и пути сборки предметов, кулдауны и числа умений, базовые статы,
  тексты описаний предметов и рун. Сводка считается сравнением данных самой игры,
  а не пересказом патчноута, поэтому чисел «от себя» в ней быть не может.
  Следом — короткий пересказ патчноута Riot про то, чего в цифрах не видно
  (переработка чемпиона, смена системы): отдельным постом, со ссылкой на
  источник и подписью, что это пересказ. Строки с числами из пересказа
  выбрасываются — числа у нас только измеренные. Когда по новому патчу
  набирается достаточно данных, бот сообщает и об этом: сайт и программа
  переходят на него сами, с ближайшим обновлением базы.
  Свежесть данных — `/patch`, изменения любого патча по запросу — `/changes`.
- **Release watch** — анонс новой версии программы в #announcements.
- **Итоги дня по установкам** — в приватный канал владельца (если задан).
- `/admin` и `/collect` — ручные запуски, состояние и ключ для сбора
  статистики (только для ADMIN_USER_IDS).

Запросы к модели (итог по нескольким релизам, пересказ патчноута) идут через
`lib/anthropic.js`. Он отличает пустой счёт API от обычного отказа и пишет об
этом владельцу в личные сообщения: без модели бот работает, но молча терять
половину постов он не должен. Текущее состояние — строка `model API` в
`/admin status`.

## Настройка Discord (один раз)

1. https://discord.com/developers → **New Application** → вкладка **Bot**.
2. **Privileged Gateway Intents**: включить **Message Content Intent**
   (нужен Lab Verifier). Server Members не нужен.
3. Скопировать **Bot Token** (`DISCORD_TOKEN`) и **Application ID** (`CLIENT_ID`).
4. **OAuth2 → URL Generator**: scopes `bot` + `applications.commands`;
   permissions: View Channels, Send Messages, Send Messages in Threads,
   Embed Links, Attach Files, Read Message History, Use External Emojis.
   Administrator НЕ давать. Открыть сгенерированный URL → пригласить на сервер.
5. Создать каналы: `#meta-radar`, `#draft-duels`, `#hall-of-fame` (обычные,
   для читателей read-only) и `#submit-finds` (**форум**). В каждом read-only
   канале: Настройки канала → Права доступа → добавить роль бота → разрешить
   **Send Messages** (в форуме — Send Messages in Threads).
6. Включить у себя Режим разработчика (Настройки → Расширенные) и скопировать
   ID сервера и каналов (ПКМ → «Копировать ID») в `.env`. Все переменные с
   пояснениями — в `.env.example`; канал не задан — его функция выключена.

## Запуск

```bash
cp .env.example .env   # заполнить
npm ci
node deploy-commands.js   # регистрация слэш-команд (один раз и после изменений команд)
node index.js
```

При первом старте бот сам скачает снимок базы с GitHub Releases в `./data/` и
дальше раз в час проверяет обновления (по хэшу в `data-version.json`),
подменяя файл на лету. Если данных временно нет, команды вежливо отвечают
«Data temporarily unavailable», процесс не падает.

## Деплой на сервер (Docker)

Бот живёт контейнером рядом с коллектором статистики:

```bash
# локально: копируем без node_modules
scp -r bot $SERVER:counterplay-bot && scp bot/.env $SERVER:counterplay-bot/.env
ssh $SERVER 'cd counterplay-bot && docker compose up -d --build'
ssh $SERVER 'docker logs -f counterplay-bot'   # проверить старт
```

Код запекается в образ, поэтому после правки обязательно `--build` — простой
`restart` поднимет старый код. `restart: unless-stopped` — контейнер переживает
ребут сервера. `node deploy-commands.js` можно выполнять локально: он ходит
только в Discord REST.

## Данные

- Снимок: `DATA_DB_URL` (только чтение, better-sqlite3). Все записи бота — в
  `./data/bot.db` (дуэли, голоса, очки, лог радара, hall of fame, служебные
  отметки).
- Бот складывает все эло вместе. Окно — два последних **готовых** патча с весами
  1.0 и 0.6, как в программе: новый патч в окно не берётся, пока по нему не
  набралось данных.
- Если каких-то данных нет (мало игр), функции деградируют мягко: пороги с
  фолбэком и пометкой *small sample*, синергия без данных = 0.
- Патчи сортируются численно, мусорные (< 5% объёма) отбрасываются; радар и
  проверка находок первые дни нового патча работают по предыдущему.
