# Установщик, обновления и откат

Распространение через **Velopack**: один `Setup.exe` со всем внутри (.NET вшит,
ставить отдельно ничего не нужно) и тихое обновление при каждом запуске.

## Что где лежит у игрока

| | |
|---|---|
| программа | `%LOCALAPPDATA%\Counterplay` (папка `current`) |
| база, настройки, пулы, журнал | `%APPDATA%\Counterplay` |
| ярлыки | меню «Пуск» и рабочий стол, создаёт установщик |

## Обновление программы

При старте приложение сверяется с лентой обновлений — релизом с подвижным тегом
`latest` в `github.com/28maryshev/counterplay`. Есть новее — скачивает и
перезапускается. При запуске через `dotnet run` проверка пропускается.

**Velopack ходит только вперёд.** Переключение ленты на прошлую версию лечит лишь
новые установки: тот, кто уже обновился, останется где был. Поэтому откат —
выпуск прежнего кода новым номером, см. ниже.

## База данных — отдельно от версий

`data.db` в установщик **не входит** и обновляется сама по себе: приложение
сверяет `data-version.json` и подкачивает свежую базу **своего эло** (ранг берётся
из клиента). Источники по порядку: `data.counterplays.com`, затем релиз с тегом
`data` на GitHub.

Базы две разновидности: полная `data.db` и побакетные `data-<bucket>.db`
(silver / gold / emerald / master) — качается только своя, она в разы меньше.
Локальная отметка хранится как `bucket:version`, поэтому смена ранга сама
вызывает подкачку нужной базы.

Выкладывает базу `build\publish-data.ps1` (она публикуется отдельно от релизов
программы) — порядок обновления под новый патч описан в `PATCH_CHECKLIST.md`.

## Выпуск релиза

Нужен доступ к GitHub: токен в `GITHUB_TOKEN` либо `gh auth login` — скрипт
возьмёт токен у `gh` сам.

```powershell
# номер поднимется сам от последнего тега; заметки — файлом, в UTF-8
powershell -ExecutionPolicy Bypass -File build\release.ps1 -Upload -NotesPath notes.txt

# собрать локально, без публикации
powershell -ExecutionPolicy Bypass -File build\release.ps1 -Version 1.3.52
```

Скрипт ставит `vpk`, если его нет; делает self-contained `dotnet publish`;
собирает `Setup.exe`, полный пакет и дельту к прошлой версии; выкладывает релиз
`vX.Y.Z`; переносит ленту `latest` на него; чистит старые пакеты в `.\Releases`,
оставляя последние три (меньше двух нельзя — Velopack строит дельту от
предыдущего полного пакета).

Полезные ключи: `-Notes` строкой, `-Highlights` вступлением, `-SinceTag` чтобы
собрать ченджлог за несколько релизов, `-FeedOnly` чтобы только перевести ленту
на уже выпущенную версию, `-AllowInternal` чтобы пропустить проверку заметок.

**Заметки пишутся для игрока** — только то, что он видит на экране. Перед
выпуском их проверяет `build\check-notes.ps1` (ругается на внутреннюю лексику);
он же вызывается из `release.ps1` сам.

**Релиз выпускается только по просьбе владельца.**

## Откат одной командой

```powershell
powershell -ExecutionPolicy Bypass -File build\rollback.ps1              # на версию перед выпущенной
powershell -ExecutionPolicy Bypass -File build\rollback.ps1 -To 1.3.45   # на конкретную
powershell -ExecutionPolicy Bypass -File build\rollback.ps1 -DryRun      # показать план и выйти
```

Собирает прежний код из тега в отдельном `git worktree` (рабочая копия не
трогается) и выпускает его **новым номером**. Для программы это обычное
обновление вперёд, поэтому доходит до всех, включая тех, кто уже на сломанной
версии. Заметки пишутся отдельно: автоген перечислил бы изменения, которых в
этой сборке как раз нет.

## Подпись

Сборка не подписана — SmartScreen предупреждает при первом запуске у новых
пользователей. Сертификат подписи кода стоит денег; пока репутация нарабатывается
количеством установок.
